# DD-CoMB

**Dempster–Dirichlet Combination of Multiple Backbones** — a parameter-free,
evidential, decision-level combination of frozen heterogeneous pretrained
backbones for reliable few-shot out-of-domain image classification.

This is the reference implementation accompanying the bachelor's thesis
*"Evidential Fusion of Frozen Heterogeneous Backbones for Reliable Few-Shot
Out-of-Domain Image Classification"* (THM, 2026). It reproduces the training,
evaluation and analysis for DD-CoMB, the starting-point model DG-EoBE, and all
baselines (single-backbone EDL, MC-Dropout, deep ensembles).

## Repository layout

```
ddcomb/
├── src/ddcomb/          # the Python package
│   ├── data/            # datasets, dataloaders, embeddings, few-shot sampling
│   ├── models/          # attention fusion, DD-CoMB ensemble, baselines, backbones
│   ├── training/        # training loops and model construction
│   ├── evaluation/      # metrics, evaluation, logging, plots
│   ├── config.py        # Hydra structured configs (schemas + validation)
│   ├── pipeline.py      # end-to-end experiment orchestration
│   ├── runtime.py       # runtime/device setup
│   └── cli.py           # unified `ddcomb` command-line entry point
├── conf/                # Hydra YAML configs (dataset/, single_backbone_dataset/, stage_a_source/)
├── scripts/             # entry points + data prep + analysis/figures (see scripts/README.md)
├── slurm/               # 105 SLURM (.sbatch) jobs, one per experiment
├── kshot/manifests/     # committed few-shot split manifests (k = 1, 5, 10, 20)
├── add_results/         # the curated per-shot four-dataset supplement (+ provenance)
├── environment/         # Dockerfile, pinned torch constraints, requirements.txt
├── docs/                # method note + architecture diagram
└── tests/               # import / config smoke tests
```

Experiment **outputs** (trained weights, `kshot/results_*`, caches, logs) and the
**datasets** are intentionally not tracked — see `.gitignore`. They are
regenerated by running the pipeline.

## Installation

Python ≥ 3.10. Editable install:

```bash
pip install -e .
# with dev tooling (pytest):
pip install -e ".[dev]"
```

`torch`/`torchvision` are expected to come from a CUDA-matched build. On the
cluster we use the NVIDIA PyTorch base image (`nvcr.io/nvidia/pytorch:25.03-py3`,
torch 2.10.0+cu128) and install the remaining runtime deps with:

```bash
python -m pip install -r environment/requirements.txt
```

A ready-to-build image is provided:

```bash
docker build -f environment/Dockerfile -t ddcomb .
```

## Data

The datasets are obtained separately (not redistributed here). The four
evaluation domains are DeepWeeds, Plant Seedlings V2, BloodMNIST and SSL-Patches.
Convert each into the split/image-folder layout the configs expect with the
matching preparation script, e.g.:

```bash
python scripts/prepare_plant_seedlings_v2.py
python scripts/prepare_ssl_patches.py
```

Dataset paths are defined in `conf/dataset/*.yaml` and
`conf/single_backbone_dataset/*.yaml`.

## Pretrained backbones

Backbone weights are **not** stored in this repository. They are obtained one of
two ways:

- **Auto-downloaded on first use** (cached under your Torch-hub / Hugging Face
  cache, e.g. `~/.cache`): DINOv2 ViT-B/14 (`torch.hub`, facebookresearch/dinov2),
  ConvNeXt-V2-Tiny (`timm`, `pretrained=True`), CLIP ViT-B/16 (`open_clip`,
  `laion2b_s34b_b88k`), MAE ViT-B/16 (`timm`), and the supervised ImageNet-1k
  backbones (`torchvision`). No manual step is needed beyond network access on the
  first run. This covers DD-CoMB's main modern pair, DINOv2 + ConvNeXt-V2.

- **DINOv3 (license-gated)** cannot be auto-downloaded. Request access at
  <https://github.com/facebookresearch/dinov3>, download the checkpoints, and point
  the code at them with environment variables:

  ```bash
  export DINOV3_REPO=/path/to/dinov3            # a git clone of the DINOv3 code repo
  export DINOV3_VITB16_WEIGHTS=/path/to/dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth
  export DINOV3_CONVNEXT_TINY_WEIGHTS=/path/to/dinov3_convnext_tiny_pretrain_lvd1689m-21b726bb.pth
  ```

  The DINOv3 SLURM jobs default these to `/home/magz94/weights/…`. DINOv3 is only
  used by the DINOv3-specific experiments; the core method does not require it.

## Reproducing the experiments

Everything runs through Hydra. Use the unified CLI or call the scripts directly
(equivalent):

```bash
# 1. Build the few-shot manifests (already committed under kshot/manifests/,
#    rebuild only if you change the sampling)
ddcomb build-manifests

# 2. Few-shot sweep for DD-CoMB / fusion on a dataset
ddcomb sweep-kshot dataset=deepweeds_no_bg_mergeval

# 3. Single-backbone and baseline sweeps
ddcomb sweep-single-backbone-kshot dataset=plant_seedlings_v2_split
ddcomb run-deep-ensemble dataset=bloodmnist_224_imagefolder_mergeval

# See all commands:
ddcomb --help
```

`ddcomb <command>` simply forwards to `scripts/<script>.py`, so
`ddcomb train-fusion mode=stage_d ...` and
`python scripts/train_fusion.py mode=stage_d ...` are identical.

### On SLURM

Each experiment has a job in `slurm/`. The jobs assume the repository lives at
`/home/magz94/ddcomb` on the cluster and run inside the NVIDIA PyTorch container,
installing `environment/requirements.txt` on top. Submit e.g.:

```bash
sbatch slurm/dino_cnx_baselines_and_rules_deepweeds.sbatch
```

If your repository path differs, update the `--container-workdir` / `cd` lines
(they point at `/home/magz94/ddcomb`).

### Analysis, tables and figures

After the runs complete, the post-hoc scripts turn `kshot/results_*` into the
thesis tables and figures (see `scripts/README.md`). For example, the curated
supplement in `add_results/` is produced by `scripts/make_four_dataset_table.py`
(provenance in `add_results/README.md`).

## Reproducibility notes

- Few-shot splits are fixed and committed (`kshot/manifests/`, 880 manifests).
- `torch`/`torchvision` are pinned via `environment/constraints-nvidia-pytorch.txt`.
- For a fully frozen environment, run `pip freeze` after a successful run and
  commit it as `environment/requirements.lock.txt`.
